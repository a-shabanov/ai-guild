Device PIN protection, settings subpages and visible update status are now available in the web/PWA and iOS sources.

### Changes

- Keep account sign-in through passkeys separate from unlocking a saved app session with a six-digit PIN and optional device verification.
- Add a numeric keypad, PIN confirmation, authenticated PIN changes and persistent retry limits. Each device configures its own PIN.
- Encrypt the native iOS session token in device-only Keychain storage; retain PIN fallback when Face ID / Touch ID is unavailable.
- Split Settings into App protection, Sign-in methods, Devices, Notifications, Appearance and About. Native also includes Participants.
- Show newer release availability in Settings/About; check when opening/returning to the app. Web also checks while visible and offers an Update action.
- Keep live version checks and app-lock responses out of the offline cache.
- Preserve the primary sign-in screen independently of the selected settings subsection.

### Upgrade and limitations

Migration 015 adds per-session app-lock fields. Existing browser sessions older than ten minutes must sign in again before creating their first PIN. A new browser sign-in establishes a new saved session and requires PIN setup again.

PWA unlocking requires an internet connection. Locking clears private read/attachment caches while preserving queued comments. Browser verification can use device biometrics or a device code; it cannot require a particular Face ID / Touch ID sensor.

The server, web and iOS sources share the repository release version/build. Native update notices compare this server release; native store/TestFlight distribution and physical-device biometric validation remain separate work. This release includes native source, not an App Store binary.

### Validation

All 122 tests passed. TypeScript checks, release/offline assets, server app-lock/device/two-factor tests and web navigation/PWA/localisation/update tests were run on isolated release sources. Local browser and simulator checks covered the keypad, settings navigation, PIN-change cancellation, current/newer releases and failed update checks. The iOS simulator build succeeded.
