Offline projects no longer fail with a null.filter error.

### Changes

- Reject missing, malformed and incorrectly shaped list responses before views use their data; a failed optional task count cannot crash the project screen.
- Show a clear offline state and a retry button for screens that have not been saved on the device.
- Rebuild failed screens when connectivity returns while preserving already loaded screens and task drafts.
- Cache only readable non-null API JSON, await cache writes and keep useful saved data when a later response is malformed.
- Delete corrupt cache entries and return an explicit offline response when no usable saved data exists.
- Continue to show valid fresh server data when browser storage cannot accept a cache write.

### Validation

All 25 offline, navigation, PWA push and localisation tests passed. Three offline tests cover valid cached data, missing/corrupt cache, malformed successful responses, full storage and session-expiry cleanup.
Fourteen mobile Chromium checks with a real service worker verified null/HTML responses, cold offline launch, corrupt cache, retained projects, missing-screen messages, retry, recovery and private-cache cleanup. Request failures were simulated at the fixture server in addition to browser offline mode.

Physical iPhone and WebKit execution were not tested. Only previously fetched data in the current offline cache can be read without a connection.
