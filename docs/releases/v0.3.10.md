PIN setup is now optional, and quick unlock is offered separately after the PIN is saved.

### Changes

- Skip PIN creation after sign-in and create it later in Settings → App protection. The choice persists for the saved browser/native session.
- Remove the quick-unlock checkbox from the keypad. Show a dedicated Connect / Not now screen after creating the PIN.
- Ask for biometric/passkey confirmation only after Connect. Cancellation or failure retains the PIN without enabling quick unlock.
- Allow initial PIN enrollment in an older valid saved session. Configured PINs still require the current code for changes; skipping cannot bypass a configured PIN.
- Bind quick-unlock enrollment challenges to the account, session and enrollment purpose. Enable the shortcut only after successful verification.

### Upgrade and limitations

Migration 016 adds the optional PIN-setup choice to browser sessions. Browser quick unlock uses passkeys and cannot require a particular biometric sensor. Native iOS sources use device-bound Keychain biometrics; physical-device validation and native binary distribution are not included.

### Validation

TypeScript checks and the full isolated release test suite passed. Browser checks covered skipping, reloading and entering PIN setup from Settings. View tests cover PIN confirmation and a cancelled quick-unlock prompt. iOS simulator build and AppState checks covered skip, reconnect, later enrollment and Not now.
