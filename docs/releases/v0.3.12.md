The web interface is now available in Spanish.

### Changes

- Choose ES in the language selector, open any page with `?lang=es`, or let a Spanish browser language select it. The choice is saved on the device, as for English and Russian.
- Dates, relative time and number separators follow Spanish conventions. Task titles, comments, project names and attachments remain as written.
- A phrase missing from a catalogue falls back to English instead of the Russian source text.
- The offline shell includes the Spanish catalogue, so installed PWAs receive it with this release.
- The server keeps running when Postgres drops a connection, instead of exiting with an unhandled error.
- The Edit button on the accounts page is translated.
- A host of many teams can run the core with a schema, file directory and public address per request. This stays off unless `DB_SCOPED` is set, so a plain install behaves as before. The same change stops two-factor login asking for a second connection inside a transaction, and stops a failed read of the VAPID keys from being cached until restart.

### Upgrade and limitations

There are no migrations or API changes. Native iOS is not localised. Text produced by the server, such as API errors, push notifications and the web app manifest description, is not translated. Amounts keep the `$1,234.56` format in every language. The translation has not been reviewed by a native speaker.

### Validation

TypeScript checks and all 161 release tests passed, including language selection, placeholder preservation, matching keys across catalogues and the offline shell entries. In a browser with demo data, the main screens, all settings sections and the sign-in page were checked in Spanish with no Russian text left, and 10 screens were checked at phone width without horizontal scrolling. Dialogs that open only after an action, and updating an already installed PWA on a device, were not exercised.

Production was verified before publication: the 0.3.12 (24) container passed its healthcheck, all deployed runtime files matched the release commit, the Spanish catalogue and service worker were served, the sign-in page opened in Spanish, and authenticated REST and MCP requests worked. The Postgres reconnection fix was not exercised by restarting the production database.
