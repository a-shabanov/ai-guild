Push notifications can now be configured by event category across an account's devices.

### Changes

- Add switches in Settings for results, comments and mentions, status changes, assignee changes, new tasks, attached files and other task activity.
- Save each change automatically and revert its switch when saving fails.
- Apply preferences before Web Push or APNs delivery to every device of that account; preserve existing defaults for accounts that have not configured them.
- Keep muted events in the inbox and task history. Explicit test notifications remain available.
- Add authenticated GET/PATCH /api/push/preferences and an additive notification_preferences table. Merge concurrent changes atomically and reject unknown categories or non-boolean values.
- Avoid offline caching of preference reads so stale switches cannot imply that a notification setting was saved.

### Validation

All 33 API/Web Push integration tests and TypeScript checks passed, including disabled attachment delivery through APNs, all categories on multiple Web Push devices, inbox retention, strict account isolation, concurrent patches and test notifications.
Eleven mobile browser checks verified saving, reload persistence, simultaneous changes, failed-save rollback, unavailable settings, dark Russian UI and light English UI. JavaScript syntax and release metadata were validated.

Physical iPhone delivery and native iOS settings UI were not tested; the web settings apply to existing native subscriptions too.
